# Подключение реальной диспетчеризации LadyGo

Обновление добавляет реальную цепочку заказа: заказ пассажира → поиск ближайшего свободного водителя → персональное предложение на 25 секунд → атомарное принятие одним водителем → обновление статусов → GPS водителя для пассажира.

## 1. Что уже добавлено в код

- `supabase/migrations/20261123230000_ladygo_live_dispatch_v1.sql`:
  - таблицы `driver_presence`, `driver_locations`, `order_offers`, `driver_push_tokens`;
  - поиск онлайн-водителей с GPS не старше 90 секунд в радиусе до 80 км;
  - по одному активному предложению на водителя;
  - срок предложения 25 секунд и переход к следующему водителю после истечения/отказа;
  - атомарное принятие заказа через блокировку строки заказа;
  - статусы «Принят» → «На месте» → «В пути» → «Завершён»;
  - RLS для предложений и координат; пассажир читает только координаты назначенного ему водителя;
  - realtime-публикация заказов, предложений и GPS.
- `src/LadyGoApp.js`: заказ создаётся в `orders`, водитель выходит на линию, видит личные предложения, принимает/отклоняет заказ и меняет статус поездки; пассажир видит состояние заказа и GPS.
- `app.json`: Android foreground location service и разрешение фоновой геолокации при активной смене водителя.
- Push-код использует существующую Edge Function `send-driver-offer-push`.

## 2. Обязательное действие в Supabase

Код в GitHub сам по себе не меняет удалённую базу Supabase. Перед запуском сделай резервную копию БД, затем примени миграцию через Supabase CLI:

```bash
supabase link --project-ref itlzvcklnxznrtaqjttc
supabase db push
```

Если CLI не настроен, открой файл миграции и выполни SQL в Supabase Dashboard → SQL Editor. Не запускай его повторно после успешного применения: сначала проверь таблицу `supabase_migrations.schema_migrations`.

Миграция рассчитана на текущую схему LadyGo. Если в рабочей базе названия колонок или ограничения отличаются, сначала нужно сверить их с фактической схемой.

## 3. Push-уведомления водителю

Realtime-предложения работают при открытом приложении. Чтобы водитель получал push, когда приложение свёрнуто:

1. Разверни Edge Function:
   ```bash
   supabase functions deploy send-driver-offer-push
   ```
2. В Supabase включи расширения Vault и pg_net.
3. Создай в Supabase Vault секрет с точным именем `ladygo_push_webhook_secret`. Значение должно быть случайной строкой не короче 24 символов. Не добавляй его в GitHub или приложение.
4. Убедись, что Edge Function использует автоматические секреты Supabase `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.

Если Vault/pg_net не настроены, триггер не ломает создание заказа, но push не отправляется. В этом случае остаётся realtime при открытом приложении.

## 4. Как проверить реальный заказ

Нужны два Android-устройства и два разных аккаунта:

1. Аккаунт водителя должен быть одобрен администратором (роль `driver`).
2. Водитель открывает LadyGo, разрешает геолокацию «Всегда» и уведомления, нажимает «Выйти на линию».
3. У пассажира выбираются реальные адреса подачи и назначения, затем нажимается «Заказать поездку».
4. Заказ появляется в `orders`, сервер выбирает ближайшего свободного водителя и создаёт запись в `order_offers`.
5. Водитель видит предложение и нажимает «Принять заказ». Сервер атомарно назначает его, другие предложения закрываются.
6. Водитель отмечает «Я на месте», «Начать поездку», «Завершить поездку». Пассажир видит статусы и координаты назначенного водителя.

Для первого теста держите оба приложения открытыми. Затем отдельно проверьте push при свёрнутом приложении и фоновую геолокацию Android.

## 5. Текущие границы

- Радиус поиска сейчас 80 км; его нужно настроить под фактический город и плотность водителей.
- Водитель должен иметь подтверждённую роль и заполненный профиль автомобиля.
- Для push требуется отдельное развёртывание Edge Function и Vault secret.
- Расчёт тарифа зависит от Edge Function `pricing-service` и конфигурации тарифов. Если она не развёрнута/не настроена, приложение использует текущую предварительную оценку маршрута; перед коммерческим запуском нужно проверить тарифы на реальных маршрутах.
- Это не подключает эквайринг/онлайн-оплату.
- Фоновая геолокация Android требует явного разрешения пользователя и постоянного системного уведомления во время смены водителя.
- До теста на двух реальных устройствах и проверки фактической базы нельзя считать диспетчеризацию готовой к публичному запуску.
